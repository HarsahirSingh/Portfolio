In Progress

AI Change-Recognition Agent

I'm building an AI agent that gives change management something it's never had: full visibility into AI-related work. Hosted on Microsoft's Azure AI Foundry so it scales across the entire organization, the agent watches our ServiceNow and Azure DevOps environments and automatically identifies which changes involve AI — the fastest-growing blind spot in most change processes.

  • Daily change sensing — every 24 hours, the agent scans all new change tickets in ServiceNow and every work item moved to In Progress in Azure DevOps, then classifies each one twice: first, whether it's AI-related — either a change to an AI system or a change built with AI assistance — and second, what type of AI change it is (business-case, portfolio, portal, and others). AI-related changes carry different risk profiles; this makes them visible before they ever reach the CAB.
  • On-close verification — when a change or work item closes, the agent runs again — this time reading the complete record: discussion comments, pull requests, and the actual code changes — and locks in a final classification. The first pass catches it early; the second pass gets it right.
  • Incident assistant (chat) — the second phase adds a chat interface for incident response: describe the symptoms and which teams might be responsible, and the agent searches everything those teams closed in the last 24 hours to surface the change most likely behind the incident — cutting the "what changed?" investigation from hours to minutes.

Built from real CAB experience — the question every change manager asks during a major incident is "what changed?" This agent is designed to answer it before it's asked.
